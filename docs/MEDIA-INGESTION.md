# Video, images and slide figures

The pipeline reads prose, slides, tables and video *descriptions*. It cannot
look at a picture or listen to a clip. This converts both into text, which is
the only thing an embedding model understands.

```
video   ->  Whisper transcribes speech into timestamped segments
images  ->  a local vision model writes a caption, and OCR pulls off any text
figures ->  the pictures inside .pptx decks, extracted and captioned
```

Output is JSON manifests the Node pipeline **already knows how to read**, so
`npm run build:index` picks them up with no code change.

**Where the value is here:** the presentation library is 11.5 GB across 292
decks — about 40 MB each — and a slide averages **412 characters of text**. The
substance is in the charts. Until they are captioned, the index holds only the
remainder.

**What this is not:** it does not understand video. It transcribes speech and
describes sampled frames. A rally clip with no narration produces very little,
and that is worth saying rather than implying the system watches tennis.

## 1. Getting the source files from S3

```powershell
# once
aws configure          # access key, secret, region (ap-southeast-2 for Sydney)

# see what is there before pulling 17 GB
aws s3 ls s3://YOUR-BUCKET/ --recursive --human-readable --summarize

# pull just the media
aws s3 sync s3://YOUR-BUCKET/video/  "C:\Users\User\Desktop\TA_S2\media\video"  --exclude "*" --include "*.mp4" --include "*.mov"
aws s3 sync s3://YOUR-BUCKET/images/ "C:\Users\User\Desktop\TA_S2\media\images" --exclude "*" --include "*.jpg" --include "*.png"

# or everything
aws s3 sync s3://YOUR-BUCKET/ "C:\Users\User\Desktop\TA_S2\document-resources"
```

`sync` is resumable and skips files it already has, so re-running after a
dropout costs nothing. Add `--dryrun` first to see what it would transfer.

If the bucket needs a role rather than a user:

```powershell
aws sts assume-role --role-arn arn:aws:iam::ACCOUNT:role/ROLE --role-session-name tennisexplore
```

## 2. Install the media tools

```powershell
pip install faster-whisper pytesseract pillow
ollama pull llava:7b
```

- **faster-whisper** transcribes. `small` (~0.5 GB) is fine for clear speech;
  `medium` (~1.5 GB) is markedly better on accented or noisy audio, which
  conference recordings are. Set `WHISPER_SIZE=medium` to switch.
- **llava:7b** (~4.7 GB) captions images. `moondream` (~1.7 GB) is weaker but
  leaves room for the embedding model if you are captioning and indexing in the
  same session. Set `VISION_MODEL` to change.

## 3. Run it

```powershell
# see what it would do first
python tools\media\ingest_media.py --video "C:\Users\User\Desktop\TA_S2\media\video" --dry-run

# transcribe video
python tools\media\ingest_media.py --video "C:\Users\User\Desktop\TA_S2\media\video"

# caption standalone images
python tools\media\ingest_media.py --images "C:\Users\User\Desktop\TA_S2\media\images"

# pull the charts out of the decks and caption them
python tools\media\ingest_media.py --figures "C:\Users\User\Desktop\TA_S2\document-resources\powerpoint-folder"

# try 20 first to see whether the captions are any good before committing hours
python tools\media\ingest_media.py --figures "...\powerpoint-folder" --limit 20
```

Everything is **resumable**. Transcripts skip files already done; captions
checkpoint every five images. Re-running picks up where it stopped.

Figures under ~20 KB are skipped — those are icons, bullets and logos, and
captioning them wastes minutes per deck for nothing.

## 4. Index the result

Add the media folder as another source:

```powershell
node --max-old-space-size=6144 bin/build-index.js `
  "C:\Users\User\Desktop\TA_S2\document-resources\research-pdfs" `
  "C:\Users\User\Desktop\TA_S2\document-resources\powerpoint-folder" `
  "C:\Users\User\Desktop\TA_S2\document-resources\match-data" `
  data\media
```

The build resumes, so only the new material is embedded.

Then:

```powershell
npm run ask -- "what does the injury chart in the Catapult deck show?"
npm run ask -- "find footage where the presenter discusses training load"
```

## How it is indexed

| | |
|---|---|
| **Modality** | `media` |
| **Chunk** | one per transcript segment, one per image |
| **Text** | caption + OCR text combined, or the spoken words |
| **Citation** | opens the clip at the timestamp, or names the source deck |
| **Flag** | `derived_from_image: true` |

Caption and OCR are stored separately and indexed together because they answer
different questions. The caption says *"a bar chart of injury counts by year"* —
that is what someone searching for "injury chart" will match. The OCR says
*"2021 12, 2022 15, 2023 18"* — that is what answers "how many in 2023".

`derived_from_image` matters at read time: this text was generated by a model
looking at a picture, not read off a page, so a quote drawn from it should be
framed as a description rather than as the document's own words.

Captions inherit the **internal** classification of the decks they came from
rather than defaulting to public — a chart of athlete injuries is not less
sensitive for having been described by a model.

## Rough costs on an 8 GB card

| | |
|---|---|
| Transcription | ~0.3× realtime with `small`. A 10-minute clip ≈ 3 minutes |
| Captioning | 2–6 seconds an image |
| 292 decks | expect a few thousand figures after the size filter — several hours |

Start with `--limit 20` and read the captions. If they are vague, switch to a
larger vision model before spending the hours; if they are good, let it run
overnight.
